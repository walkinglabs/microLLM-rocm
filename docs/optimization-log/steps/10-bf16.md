Status: `in progress` — single-representation FFN model policy partially kept

Experiment 030 completed the first retry contract: BF16-output GEMM plus one continuous

## New track

BF16 results do not extend the FP32 running-best line. Create `results-bf16.tsv` and a
separate figure series when this step begins.

The separate evidence is currently split into `bf16-results.tsv` for operator shapes and
`bf16-model-policy.tsv` for official-model medians. Experiment 015 proves that an exact
shape allow-list plus duplicate cached weights is not the final design.

Experiment 030 adds `experiments/030-data/raw.jsonl`, `summary.json` and
`assets/bf16-ffn-island.svg`. All four fixed FFN shapes improve, but this operator result
cannot pass the model-level keep gate by itself.

Experiment 031 integrates that island into pinned Qwen/DeepSeek with one persistent FFN
weight representation. Self-baseline speed, memory and exact-token gates pass; the selected
PyTorch full-BF16 comparison still fails 3/4 performance rows. Whole-model BF16 training
and all-workload competitive parity remain open.

Experiment 032 moves allocator activation to the prefill warm-up boundary. Both model
prefill rows cross the selected PyTorch BF16 reference; DeepSeek decode is now the sole
remaining red row.

Experiment 033 identifies GEMM as 67.64% of DeepSeek decode Kernel time. Experiment 034
adds transactional BF16 Q/K/V/O weights and a shared Q/K/V input cast. Both decode rows
improve, but DeepSeek decode remains below the PyTorch full-BF16 reference.

Experiment 035 isolates repeated host descriptor/layout construction after BF16 Kernel
time falls. Experiment 036 caches only immutable BF16 exact-shape plans. The pinned
short-prompt Qwen/DeepSeek inference matrix now passes all four PyTorch BF16 throughput
rows; mixed-precision training and broader inference shapes remain open.

Experiment 037 adds full Transformer BF16 Linear training with FP32 masters and STE
gradients. It beats the matched PyTorch BF16 autocast reference but regresses against
microLLM FP32 and does not reduce peak memory. Continuous training activation islands are
the next gate.

Experiment 038 shows cast time exceeds BF16 GEMM savings. Experiment 039 removes exactly
the predicted Q/K/V casts but regresses the two-model geometric throughput; that graph API
is discarded. A larger continuous training island is required.

Experiment 040 gives every Linear FP32 master a persistent BF16 forward mirror and updates
both in one AdamW HIP launch. Qwen/DeepSeek improve 9.4%/5.9%, while peak memory rises
7.9%/10.8%. The mechanism is retained as an explicit speed/memory trade-off. Checkpoint
state keeps only masters and moments; `AdamW::load_state` rebuilds derived mirrors.

## Design

- BF16 parameter/activation storage;
- FP32 Norm/Softmax/CE accumulation;
- FP32 master weights where required;
- BF16 hipBLASLt projection and batched GEMM;
- explicit cast rules, no implicit FP16/BF16 mixing;
- BF16 checkpoint load without full FP32 persistent duplicate where possible.
- BF16 activation islands so adjacent compatible operators do not cast every Linear input.

## Required tests

- all Tensor/view/transfer semantics;
- per-op PyTorch BF16 tolerances;
- full official logits and generated tokens;
- multi-step loss/gradient/parameter trajectory;
- overflow/non-finite checks;
- throughput and allocated/reserved memory comparison against PyTorch BF16.

## Falsification

If GEMM speeds up but whole model does not, remaining FP32 reductions, casts, copies or
launches are the true bottleneck. Do not describe BF16 as an optimization without
end-to-end improvement.

## Keep gate

Correctness and model-level speed/memory evidence pass on at least Qwen and DeepSeek
Distill; FP32 reference remains unchanged.
