# Experiment 123：32个scale全失败，但边界还没有封死

## 问题

Experiment 122只测了一个全局scale对。一次失败可能只是数字选错，不能证明“全局scale”这个设计错。

FP8可以把连续小数想成只有有限格子的尺子。`scale`决定每一格代表多大：

- scale太小：尺子很精细，但大数会顶到头，也就是饱和；
- scale太大：不容易顶到头，但相邻格子太远，小数被粗糙地四舍五入；
- 权重和activation的数值范围不同，两个scale必须分开测。

## 实验合同

运行前固定一个4×4网格：

```text
activation  0.00625, 0.0125, 0.025, 0.05
weight      0.00125, 0.0025, 0.005, 0.01
```

两个官方模型各跑1个FP32参考和16个FP8候选，共34个fresh process。每个候选比较最后位置完整
151936维logits；门为`max <= 0.2`、`RMS <= 0.05`且top token相同。速度不能覆盖精度失败。

GPU2运行前连续三次use/VRAM均为0%，每个worker前VRAM为0%，结束后最大VRAM 2%、use 5%。

## 结果

34/34个worker执行成功，32个FP8候选中0个通过精度门。

|---|---:|---:|---:|---:|---:|

## 能说什么，不能说什么

能说：当前32个候选都远离精度门，单个静态scale结果不是偶然噪声。

不能说：所有全局scale都失败。Qwen的最佳activation恰好是最大候选0.05，说明搜索区间可能截断了
下降趋势。DeepSeek的最低RMS候选还改变top token，所以表中的“最佳”按固定规则优先保留top相同。

## 决策

- 拒绝当前网格作为模型策略；
- FP8仍不设为默认，也不声称官方模型低精度推理已通过；
- 下一实验只把activation上边界扩到0.1/0.2，并保留完整logits门；
- 若扩展后仍远离门，再实现weight per-tensor amax，不继续盲搜更多全局数字。
