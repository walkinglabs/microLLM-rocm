# 同一个办法，换长短输入还有效吗

日期：2026-08-24

前面的Grouped优化只证明了rows=512。rows可以理解成“这次一共有多少个token位置要一起算”。
这次增加：

    rows=256：更短
    rows=1024：更长，或batch=2且每条512

Qwen、DeepSeek的QKV和gate/up一共8种情况，每种跑3个全新进程。前64个候选全部通过数值检查，
稳定地址方案全部更快，范围是1.124倍到1.695倍。

一次pilot曾说DeepSeek rows256即使每次重新准备也快1.051倍。但三进程中位数变成0.964倍，
推翻了单次结论。正式设计仍然要求地址稳定。

下一步还不能直接说“rows1024模型一定快”。B1/T1024和B2/T512虽然矩阵乘法shape相同，
Attention和batch行为不同。必须分别跑完整模型才知道。
