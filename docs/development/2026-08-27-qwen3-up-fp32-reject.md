# Qwen3全局up-FP32候选拒绝

日期：2026-08-27
状态：精度通过，性能拒绝

候选让FFN up保持FP32，gate/down与全部Attention使用BF16，Cache使用BF16。完整矩阵执行
64/64 worker、32/32聚合行和24/24精确KV容量。23行直接匹配Transformers BF16；其余9行没有
被悄悄改写成pass，而是在共同输入的首次分叉处逐项对齐PyTorch FP32。

新增T128/B2 step22和T512/B2 step2中，候选分别选择4226和2955；PyTorch FP32与microLLM FP32
给出同样答案，Transformers BF16分别选择3270和1096。结合既有状态，候选oracle为8/8。

正式性能门使用5个场景、每策略每场景3个新进程、2次热身和5次测量。四个cached-decode场景
均通过，吞吐比为0.972–0.981；T512/B2 prefill只有0.8875x，延迟为1.1268x。五场景吞吐几何
均值0.9578x，低于0.97门。常驻权重准确增加176,160,768字节。

因此全局up-FP32不成为默认。下一次只允许测试一个新条件：decode使用up-FP32，prefill仍使用
可融合的全BF16；它需要双权重表示，必须重新核对额外内存，不能把本节点的数字外推过去。
