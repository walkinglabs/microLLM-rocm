# 两种优化一起打开，会不会互相打架

日期：2026-08-24

现在有两种显式优化：

    Attention把Q、K、V一起提交
    FFN把gate、up一起提交

它们分别正确，不代表一起打开也正确。可能出现的问题包括：一个registry清掉另一个、两个Arena
拿错地址、显存相加超门，或者只命中其中一个。

所以每个模型测试四种情况：都不开、只开QKV、只开gate/up、两个都开。24个全新进程里，
两个都开时Qwen快1.0655倍，DeepSeek快1.0474倍；相对QKV-only还多1.0199倍和1.0172倍。

每个打开的策略都准确执行每层每次一次，关闭的一边永远是零。完整logits在BF16误差范围内，
top-1相同，peak增加约0.34%和0.17%。

还有一个好现象：QKV先把GroupedGemm底层准备好以后，gate/up Kernel准备从约57ms降到
约0.24ms。但总setup仍约205–214ms，服务必须在接收用户请求前明确支付，不能假装不存在。

结论是“可以显式组合”，不是“所有机器默认打开”。编号和shape仍要匹配真实环境。
