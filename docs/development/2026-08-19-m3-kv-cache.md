# 2026-08-19 — M3 real per-layer KV cache

## Contract

Cache projected and RoPE-rotated K/V tensors for every layer. A cached forward call
accepts exactly one new token, computes its Q/K/V once, appends new K/V, attends over
the cached prefix, and returns one-token logits. It must not implement cache behavior
by replaying cached token IDs through the complete model.

## Implementation

- each layer stores K/V with shape `1 x kv_heads x cached_sequence x head_dimension`;
- new K/V receives RoPE using the absolute cache position;
- GQA expands cached K/V heads only for Attention computation while retaining compact
  `kv_heads` storage;
- cached Attention sees only existing prefix K/V, so ordinary last-dimension Softmax
  is causal by construction;
- cache validates model layer count, maximum length, token shape, and capacity;
- reset releases layer tensors and returns position to zero.

## Verification

For both MHA and GQA tiny configurations, each token in a four-token sequence is run
through cached forward. Its logits are compared with the final-position logits from
a full forward pass over the same prefix. Every vocabulary value at every position is
within `2e-5`. Cache position and stored sequence length reach four and reset to zero.

## Boundary

The first cache path is CPU float32 and batch one. Appending currently materializes a
larger K/V Tensor, so it removes projection recomputation but not allocation/copy
growth. Preallocated cache storage, batch support, HIP kernels, and generation are
separate next steps.
