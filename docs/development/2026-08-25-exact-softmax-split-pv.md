# 只把最后一步分给更多小组

## Attention最后在做什么

模型先为每个历史位置算一个“重要程度”，再把这些重要程度变成总和为1的概率。最后，它用概率
给每个历史value加权：

```text
输出 = 概率0×value0 + 概率1×value1 + ... + 概率T×valueT
```

旧finalize让一个线程为一个输出列从头加到尾。上下文有2048个位置时，这条链很长，而且一个
batch只有24个Attention head block，MI300X很多计算单元没有工作。

## 新实验只改变最后一段

score和softmax继续使用已经通过完整模型位级门的顺序。P×V把2048个位置切成16段，16个block
分别算partial，最后按split 0到15合并。

S1故意也走新接口，但不真正切分。它必须与旧结果位级相同，而且实际只有旧速度约一半。这是
很重要的反例：新增buffer和Kernel本身会变慢，S16的收益确实来自并行工作。

## 结果

160个新进程覆盖两模型、长短上下文、两种batch和两种cache dtype。所有16格都选择S16，至少快
1.2749倍，最多2.9549倍。完整context误差最多约39亿分之一。

这仍不是“模型已经安全”。很小的误差经过28层和64个token可能被放大。下一步必须保存并比较
DeepSeek所有303,872个cached logits，不能只看最后生成token相同。
