# 相同句子复制八份，模型为什么可能给出不同答案

## 先排除最直观的Bug

如果B8的第3行写到了第4行，或者GPU argmax选错位置，batch不同当然会生成不同token。审计先检查：

- 同一个batch的所有输入行是否得到完全相同的151,936个logits；
- 两个新进程是否逐位重复；
- CPU读取完整logits得到的argmax是否等于GPU选出的token。

这三项全部通过，所以行索引和argmax不是当前解释。

## 数学相同，不代表浮点加法顺序相同

GEMM会根据矩阵的M维，也就是batch大小，选择不同tile或算法。实数数学里答案相同；有限精度中，
加法顺序不同会产生小差异。

这里step0的完整logits已经差约0.05–0.07。前两个token虽然没变，差异继续经过模型后，step2最大
达到0.1978，最终让B1/B8与B2/B4选择不同token。

## 下一步怎么定位

当前模型同时用了BF16 FFN和BF16 Attention。下一实验只看step0，依次运行：

```text
全FP32
只BF16 FFN
只BF16 Attention
两者都BF16（当前）
```

如果全FP32跨batch接近或完全一致，而某个BF16 island突然变差，问题范围就缩小了。证据不足前，
不通过固定B2/B4来隐藏B1/B8失败。
