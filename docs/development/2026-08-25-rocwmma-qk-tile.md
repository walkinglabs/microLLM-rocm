# 2026-08-25 — 用“矩阵积木”计算 Attention 分数

## 先用初中数学理解

Attention要比较每个词和前面每个词有多像。最直接的办法，是把两个长度为64或128的数字列表
逐项相乘再相加。句子有2048个位置时，这个动作要重复几百万次。

MI300X里有专门一次处理小矩阵的计算单元。rocWMMA把它包装成“积木”：一个wave一起搬入
16×16或32×32的小块，做乘加，再把结果写出去。这里的wave不是64个互不相关的小程序，而是
64个线程合作完成一块矩阵。

## 为什么先做独立试验台

如果一开始把矩阵积木、因果遮罩、softmax、V加权和模型全写在一起，结果慢时我们不知道是哪一
层错了。本轮只算QK分数，并准备三个完全相同的问题：

1. CPU逐项算，作为答案；
2. GPU每个线程逐项算，作为标量基线；
3. rocWMMA用矩阵单元算；
4. hipBLASLt用成熟库算。

程序不是只检查几个角落，而是把完整`T×T`结果搬回并逐项比较。16个shape、3次新进程，共
48次全部通过。

## 看懂结果

T512时，矩阵积木比同条件hipBLASLt快约1.65–1.78倍；T2048、宽度128时，它反而只有0.688倍。
原因不是矩阵单元失效，而是这个教学kernel还会重复读数据，并把巨大的分数表完整写回显存。

所以本轮结论不是“我们写完Flash Attention”，而是：积木可以用，也找到它会输的题目。下一步
要让分数、最大值、指数和V加权在小块内部连续完成，避免保存整张分数表；做不到就回退。
