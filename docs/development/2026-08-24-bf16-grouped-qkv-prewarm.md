# 把 Grouped QKV 准备移到用户请求之前

日期：2026-08-24

普通BF16模型第一次运行本来就慢约5秒，因为许多底层plan和GPU代码在第一次使用时才准备。
GroupedQKV如果也等到用户请求再准备，第一次请求会到约5.74秒。

新API让服务在“开始接客”前主动跑一次假的QKV：

```text
加载权重
→ 准备BF16权重
→ 注册精确算法
→ 开QKV Arena
→ prewarm(rows=512)
→ 才允许请求进入
```

Qwen/DeepSeek预热花915/886ms，随后第一个真实请求降到4852/4795ms，比lazy grouped快
892/947ms。把预热和请求相加后仍约5.7秒，所以它只是搬动工作时间，没有凭空消除工作。

重复预热同一个rows会返回`already_warm`，不会再运行。换设备、重设Arena或换rows后必须重新准备。
默认CLI不预热；只有明确管理服务生命周期的人才应该开启。
